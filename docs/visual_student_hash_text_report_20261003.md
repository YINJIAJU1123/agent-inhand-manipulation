# Hash-text language-conditioned student (2026-10-03)

## Motivation

The frozen SigLIP2 path remains unavailable on the GPU host because the Hugging Face model download times out. To continue the language-conditioned stage without mislabeling the result, this run uses a deterministic, versioned text-string adapter.

The adapter hashes word and character n-grams from the actual instruction string into a normalized 64-D vector. It is a deployment fallback and a contract test; it is not a pretrained semantic language model.

## Contract

- Visual task: `BrainCo-Direct-Revo3-VisualSemanticReorient-Cube-v0`
- RGB-D feature width: 1,060
- Language feature width: 64
- Language mode: `hash`
- Action dimension: 21
- Action scale: 1.0
- Vision stride: 2
- History: 8 observations
- Data: round-8 unified cache, 152,657 samples and 2,379 episode groups
- Evaluation: 96 episodes, four environments, 600-step horizon

The training cache is generated by `scripts/vision/cache_hash_text_features.py`. The closed-loop evaluator requires `--language-mode hash`, and checkpoints now record the language mode to prevent accidental one-hot/hash mismatch.

## Closed-loop result

| Seed | Success | Drop |
|---:|---:|---:|
| 1 | 86.46% | 12.50% |
| 3 | 81.25% | 14.58% |
| 5 | 80.21% | 13.54% |

Mean success is **82.64%** with approximately **2.7 percentage points** standard deviation. This is comparable to the one-hot language condition on the same 96-episode budget, showing that the actual instruction string is reaching the recurrent action policy without breaking the visual control path.

## Current interpretation

The hash-text run is an interface and deployment milestone. It does not establish open-vocabulary semantic understanding. The next upgrade is to replace the hash adapter with a versioned frozen CLIP/SigLIP text encoder once weights are available, keeping the same checkpoint metadata, 21-D action head and evaluation protocol.
